# Graphia M4.1.2 Benchmark Report

## Overview and methodology

Performance closure uses deterministic synthetic repositories generated by `benches/generator.rs` with fixed seed metadata.

| Dataset | Files | Purpose |
|---|---:|---|
| Small | 100 | Fast regression and per-operation latency |
| Medium | 1,000 | Representative incremental workload |
| Large | 5,000 | Opt-in scale and memory stress workload |

Fixtures contain Rust, Python, TypeScript, and Go source with definitions, calls, and imports. Metadata records source bytes, symbols, edges, per-language counts, and seed. Large generation is enabled with `GRAPHIA_BENCH_LARGE=1` because setup parses and resolves approximately 5,000 files.

## Harness and measurements

- `benches/performance.rs` emits CSV rows for clean build, native index load, single-file incremental update, 10/100-file bursts, fallback reconcile, BFS, impact, neighborhood, context generation, and MCP invocation.
- `benches/rss.rs` measures peak process memory through Windows `GetProcessMemoryInfo` or Unix `getrusage`.
- Unsupported or failed OS measurement emits `UNAVAILABLE` plus reason; zero is never used as fake RSS.
- Incremental comparison uses same repository state and compares selective update latency with clean rebuild latency.
- Graphify comparison is `UNAVAILABLE` without its external Python harness.

## Results record

The benchmark harness and regression assertions are closed and **PASS**. Task 8 verified deterministic metadata, explicit RSS availability semantics, and amortized single-file incremental latency below clean rebuild latency. Task 9 verified one-file real-runtime incremental behavior and `incremental_graph == clean_rebuild_graph`.

No stable 100/1,000/5,000 CSV capture was available for this execution because benchmark runner could not be started in current environment. No numeric values are invented here. Run:

```powershell
$env:GRAPHIA_BENCH_LARGE = "1"
cargo bench --bench performance -- --noplot
```

Output schema: `dataset,files,source_bytes,nodes,edges,stage,latency_ns,peak_rss_bytes`. Record machine, OS, Rust version, and whether RSS is numeric or `UNAVAILABLE` beside any published capture.
