# M4.1.3 Final Report

## 1. Hidden warning audit

Repository-wide Rust suppression search is empty. Unused flow helpers and the
benchmark enum suppression were removed. `cargo check --all-targets
--all-features` passes.

## 2. Selective incremental architecture

`IncrementalWorkspace::apply_changes_selective` reparses changed files, merges
new semantic dependency hints with the old affected closure, and splices a
fragment graph into existing file-owned nodes and edges. Resolution refreshes
against the global parsed workspace, so newly introduced imports, references,
types, inheritance, implementations, instantiations, and exports are visible.
Normal edits set `full_rebuild=false`; unknown rename uses explicit fallback
reason/counter.

## 3. Affected resolution behavior

File ownership indexes remain authoritative after every splice. Affected closure
tracks import/type dependents and graph-connected consumers. Canonical graph
equivalence is covered by incremental workspace tests; broader resolver work is
performed only after component mutation.

The pending-resolution index now contains only references with no current
definitive edge. A selective update removes entries owned by files being
re-resolved, then inserts their still-unresolved references after resolution.
Provider surface diffs query direct `(relation kind, semantic name)` buckets;
they include both old and new declarations plus exports/re-exports. The update
summary exposes direct lookup and examined-entry counts, with
`full_pending_scans == 0` on the ordinary path.

## 4. Unified semantic pipeline

Clean repository builds and incremental fragments use `build_graph`, followed by
the same cross-file resolver, validation, and canonicalization routines. Daemon
and MCP storage entry points use the existing storage/update engine.

## 5. Dataflow architecture

`DataFlowGraph` slices each function from its exact Tree-sitter-derived
start/end location before local-flow extraction, creates function-scoped stable
variable/return entities, and emits assignment, return, and resolved argument
references. Structural `Calls`, `Contains`, and `Imports` are not value-flow
edges. Unsupported source roots report no inferred flow instead of fabricating
paths.

## 6. MCP concurrency/cancellation architecture

Stdio input, bounded four-worker execution, cancellation notifications, and one
serialized writer are separated. Request tokens are registered before dispatch,
removed on completion, and cancellation is consumed while workers run. Capacity
overflow returns a bounded internal-capacity error.

## 7. Benchmark methodology

Existing generator retains Small (100), Medium (1,000), and opt-in Large (5,000)
tiers. Runtime incremental benchmark uses the storage update path and reports
selective changes.

## 8. RSS methodology

RSS uses platform APIs with explicit `UNAVAILABLE` state; no zero substitute.
The performance bench defaults to bounded child-process stage execution and was
smoke-tested with an isolated Small clean-build stage.

## 9. Runtime verification

Selectivity/new-dependency, function-isolated AST flow, in-flight MCP stdio
cancellation over a 20,000-node traversal, and daemon process generation tests
pass. Benchmark child-stage and daemon process smoke also pass.

## 10. Tests

`cargo fmt --check`, `cargo check --all-targets --all-features`,
`cargo clippy --all-targets --all-features -- -D warnings`, and
`cargo test --all-targets --all-features` passes (205 tests). The opt-in Small
benchmark smoke also completed through clean build, native load, one-file
incremental update, and burst stages.

## 11. Known limitations

Dynamic dispatch remains bounded by existing resolver candidate limits; languages
without AST local-flow extraction report no fabricated value-flow paths.

## 12. Final milestone status

**PASS.** Runtime proofs pass: affected resolution avoids hidden full builds,
reverse unresolved references re-resolve selectively, dependency relation
regressions match clean builds, return-flow propagates only AST return calls,
MCP cancellation is in-flight, and the real daemon burst benchmark processes
all requested files.
