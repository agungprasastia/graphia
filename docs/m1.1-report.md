# M1.1 Scope-Aware Resolution Engine Report

## Overview
The M1.1 Scope-Aware Resolution Engine implements deterministic, scope-aware, import-aware, alias-aware, and receiver-aware symbol resolution for 16 programming languages across static call sites.

## Resolution Architecture

The resolution system lives in `src/resolve/` and is divided into modular components:

1. **Scope Tree (`src/resolve/scope.rs`)**:
   - Manages the hierarchical scope chain: `Project -> Package / Module -> Namespace -> File -> Class / Struct / Trait / Interface -> Function / Method -> Block`.
   - Lexical lookup proceeds inner-to-outer, providing deterministic lexical shadowing semantics.

2. **Import Engine & Table (`src/resolve/import.rs`)**:
   - Parses normalized import directives for 16 supported languages.
   - Handles explicit import lists, wildcard / glob imports, aliasing (`import foo as bar`, `using Bar = Foo;`), CommonJS `require()`, and re-exports.
   - Maintains an `ImportTable` mapping file paths to resolved directives and alias tables.

3. **Candidate Generation & Disambiguation (`src/resolve/candidate.rs`)**:
   - Generates candidate symbol matches with priority ranks:
     - Priority 1: Local Lexical Scope (inner function / block)
     - Priority 2: Same-file definition / local class member
     - Priority 3: Explicit Import Alias (`import { foo as bar }`)
     - Priority 4: Explicit Import (`import { foo }`)
     - Priority 5: Receiver Method Resolution (`user.login()` -> `User::login`)
     - Priority 6: Wildcard / Cross-file Import
   - Disambiguation outcomes are strictly categorized into:
     - `Resolved { target, reason }`: Exactly one candidate at highest priority level.
     - `Ambiguous { candidates }`: Multiple competing candidates at the same priority level (bounded candidate set). Emits no false-positive edge.
     - `Unresolved`: No valid candidate reachable via scope or import boundaries.

4. **Resolution Engine Orchestrator (`src/resolve/mod.rs`)**:
   - Integrates normalized extraction results with graph construction (`src/graph/mod.rs`).
   - Populates inferred `Calls` edges with `Confidence::Inferred` and reports `ResolutionSummary` (`resolved_calls`, `unresolved_calls`, `ambiguous_calls`).

## Supported Language Semantics

- **Rust**: `use a::b::{c, d as e};`, `use a::b::*;`, `mod`, `impl` block methods, lexical functions.
- **Python**: `from foo import bar as baz`, `import foo.bar as baz`, class method receivers, module functions.
- **JavaScript / TypeScript / JSX / TSX**: `import { a as b } from './mod'`, `import * as ns from './mod'`, `const x = require('./mod')`, class method definitions, arrow function assignments.
- **Go**: `import alias "pkg"`, package scopes, struct receiver methods `(s *Server) Run()`.
- **C / C++**: `#include "header.h"`, `namespace`, class/struct specifiers, qualified method definitions `ClassName::method`.
- **Java & Kotlin**: `import pkg.Class;`, `import pkg.*;`, `import pkg.Class as Alias;`, class methods.
- **C#**: `using Namespace;`, `using Alias = Namespace.Class;`, class methods.
- **PHP**: `use Namespace\Class as Alias;`, namespaces, classes, methods.
- **Ruby**: `require 'file'`, `require_relative 'file'`, module and class methods.
- **Swift**: `import Module`, module level symbols.
- **Zig**: `const mod = @import("file.zig");`, struct declarations.

## Precision Limits & Conservatism

1. **Ambiguity Preservation**: When multiple equally prioritized symbols match a call reference, the engine preserves the ambiguity in the report and refuses to fabricate speculative edges.
2. **Import Isolation**: Symbols from unimported files are never resolved, preventing cross-module name collisions.
3. **Deterministic Ordering**: All candidates and scopes use `BTreeMap` and `BTreeSet` with canonical sorting to guarantee identical output across runs.

## Incremental Equivalence

The resolution engine interacts directly with the incremental parse cache (`.graphia/parsed.json`) and storage layer:
- Unchanged files reuse cached AST extractions (`ParsedFile`).
- Graph construction re-resolves the complete project graph deterministically from the cached IR.
- Clean rebuilds and incremental updates produce byte-identical binary indexes and JSON exports.
