# M0.5 Report

## Status

Conditional/partial. Local stage timings, deterministic benchmark assertions, and
storage measurements are recorded. RSS and Graphify comparison are unavailable
in this environment, so no claims are made for those metrics.

## Method

`benches/performance.rs` generates deterministic Rust fixtures in a temporary directory:
3, 12, and 48 sorted files. Each file contains one struct and two functions;
the source text is generated from the file index and wraps links modulo the
dataset size. The harness runs in release mode with:

```text
cargo bench --bench performance
```

It measures scan, parse/extraction, graph/resolution, exact query, bounded BFS,
JSON write, binary write, binary load, and a changed-tree incremental update.
The update starts from a clean cache/index, then modifies one file, adds one,
deletes one, and leaves remaining files unchanged. It also records node/edge
counts, source bytes, and binary index bytes. Exact benchmark output is CSV on
stdout, with `peak_rss` and `graphify` explicitly reported as `unavailable`.
Scan, parse, graph, serialization, and incremental stages run once; exact
lookup and BFS run for 1,000 repetitions and report average nanoseconds.

## Decisions

Parsing/extraction is largest measured stage, but this fixture is small and
does not establish a production-scale parallelism win. No Rayon dependency or
bounded worker API was added. Sequential parsing preserves existing behavior
and avoids scheduling-dependent complexity. Repeat builds emit equal graph and
JSON bytes, and binary bytes for every dataset.

No `HashMap` ordering is persisted. No unsafe code, CSR adjacency, mmap, or
string interning was added because no before/after measurement justified them.

## Measurement Limits

Peak RSS was unavailable: no portable stdlib process-RSS API exists for this
Windows target, and no approved process API or reproducible local command was
available during this run. Graphify comparison was attempted with audited
revision `680e3ed8edd3dc1fa1961050912941880b778207`, but no reproducible
Graphify benchmark command or installed comparison environment exists here.
These are unavailable measurements, not zero values or performance claims.

Incremental timing covers `build_or_update` after the changed-tree scenario and
includes current M0.4 persistence. It is a baseline, not proof of selective
reparsing speedup.

## Verification

The benchmark asserts repeat-build graph equality and byte-identical binary
output. Full release gates are recorded in `task-7-report.md`.
