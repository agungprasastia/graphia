# M0.4 Report

PASS.

`build` and `update` persist `.graphia/metadata.json` plus `.graphia/parsed.json`. Metadata stores normalized relative path, size, optional modification timestamp, SHA-256 content hash, language, and parser schema version. Cache and metadata schema mismatches are ignored and force a clean parse/classification path. Content hash is correctness authority; mtime alone never marks content changed.

Updates reuse parsed IR only for hash-identical files with matching language and parser schema. Added, modified, and deleted paths are reflected in current graph construction. Graph is rebuilt from current parsed IR and canonicalized on every update, re-resolving imports/calls and removing stale edges. This preserves invariant: incremental output equals clean rebuild for same final tree.

`build --clean` explicitly removes stale parsed cache, allowing only `NotFound`; other removal errors fail. CLI prints deterministic added/modified/deleted/unchanged counts. JSON, binary index, metadata, and parsed cache each use existing atomic replacement independently. Cross-artifact transaction/rollback is intentionally not implemented in M0.4; a failure can leave earlier artifacts updated while later artifacts remain previous, and callers must rerun update.

Cache loading also performs bounded semantic validation: schema, unique non-empty paths, supported language/parser schema, and source-location ownership must agree before any entry can be reused. Invalid entries fall back to clean parsing. CLI output semantics are deterministic: `changes: added=N, modified=N, deleted=N, unchanged=N`.

Malformed `.graphia/parsed.json` JSON is treated as invalid cache and triggers clean reparsing. Filesystem read errors remain fatal. Verification evidence: `cargo test --test incremental -- --test-threads=1` passes 8 tests; `cargo test --all-targets --all-features`, `cargo check --all-targets --all-features`, and `cargo clippy --all-targets --all-features -- -D warnings` pass. Tests cover hash classification, observable valid-cache reuse, malformed/duplicate-cache rejection, schema mismatch fallback, clean cache handling, add/modify/delete equivalence, and byte-identical JSON/binary persistence. CLI summary currently has pure formatter unit coverage; run-level stdout testing remains intentionally omitted because command execution is thin delegation and formatter semantics are the stable boundary.
